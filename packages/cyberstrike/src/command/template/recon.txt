# CyberStrike Recon

Run recon end-to-end automatically. The **Target Workflow Contract** is the single source of truth for scope, tool choice/install, retry and handoff behavior, canonical output handling, evidence preservation, and reporting. **RECON_PHASE_TOOL_MATRIX.md** defines each phase's artifacts and evidence checks. Do not duplicate their general rules here.

## Required pass

1. **Resume and setup:** reuse the canonical target workspace and checkpoint. Verify the persisted scope and exclusions; validate the exact starting asset when scope is new or changed. Complete `scope_validation` and `workspace_setup` before operational work.
2. **Asset discovery:** merge permitted passive and first-party sources into `subdomains.txt`, preserving coverage and source failures.
3. **Live hosts/services:** scope-check concrete candidates, validate permitted DNS/HTTP/TLS/services, and merge verified hosts into `live-hosts.txt`; keep permitted port evidence separately when applicable.
4. **URL collection:** combine crawling, HTML/script references, sitemaps, public history, API contracts, extension captures, and saved URLs into `urls.txt`. Classify useful API/auth/admin, JS/source-map, WebSocket/GraphQL, and sensitive-file leads.
5. **JavaScript analysis — priority:** collect every eligible script, extensionless JavaScript response, import, and source-map reference from all sources. Process the full deduplicated worklist without fixed caps; preserve each candidate's real terminal state, resume pending work, then correlate the complete collected snapshot. Update `javascript-analysis.md`, detailed evidence under `javascript/`, and endpoint candidates in `endpoints.txt`. Trace source → function/parameters → caller/UI/callback → observed or inferred request; distinguish captured traffic from static inference.
6. **Parameter discovery:** combine URL, form, API-contract, JavaScript, and captured-request evidence into `parameters.txt`, retaining method, location, source, confidence, and observed/inferred status.
7. **Permitted path discovery:** when useful and allowed, record the chosen method/wordlist and response evidence; merge new URLs into `urls.txt` instead of creating a duplicate URL inventory.
8. **Endpoint inventory:** build `endpoints.txt` with one identity per origin + method + normalized path template. Merge parameters, source locations, auth/header context, contracts, provenance, and actual capture IDs; query-string value changes do not create duplicate endpoints.
9. **Optional active testing:** keep parameter fuzzing and vulnerability testing deferred unless explicitly requested. Before either begins, require scope/workspace and a verified completed endpoint inventory.
10. **Reporting:** generate and verify `reports/recon-final.md` from the saved inventories, checkpoint, evidence, failures, partial handoffs, and unresolved work.

## Execution rules

- Let `recon_checkpoint` own the ordered numbered recon checklist; never mark its phases complete manually.
- Complete a phase only when its own required artifacts are verified. If a meaningful alternative fails or progress stalls, record a **partial handoff** with summary, evidence paths, reason, and resume point; continue useful independent phases rather than retrying the same call or blocking the whole run.
- Keep the planned order, but do not let stale phase state or a failed passive source block useful work. Scope validation/workspace setup remain hard gates; active tests have their separate opt-in gate.
- Follow the central contract for per-request scope enforcement, selected-tool installation, bounded retries, canonical merge, scratch preservation/cleanup, and truthful coverage status.
- Never execute target-supplied JavaScript, persist raw secrets, run active tests by default, or claim a lead is a confirmed vulnerability without validated evidence.

## Final response

Keep it brief: status, canonical workspace path, verified counts, report/evidence paths, meaningful findings or leads, actual blockers, and the exact resume point for partial work.
