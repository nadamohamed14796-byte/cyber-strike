# CyberStrike Recon

Do the work, not a long plan in chat. Follow these steps, save results, verify them, and report only verified outcomes. The phase matrix defines artifacts; `recon_checkpoint` stores progress.

## Rules

1. Keep the original CyberStrike scope rules. Check the starting asset once for a new/changed/unresolved target or policy; reuse saved scope on resume. Each real request and redirect must still pass request-level scope enforcement.
2. Choose any suitable available tool/API/CLI/helper. Check its current schema when needed. Phases are not a tool allowlist; don't run every similar tool.
3. No arbitrary source/host/URL/result/time caps. Merge partial results as they arrive. On failure, try a useful alternative or record the exact blocker. Never invent results.
4. Use one canonical root workspace and one inventory per data type. No per-host workspaces, temporary copies, or per-tool inventories. Resume unfinished work; don't repeat verified work without new evidence.
5. Recon clues are not findings. No vulnerability scanners, `session_scan`, exploit payloads, or targeted vulnerability tests unless the user explicitly requests testing and runtime/policy controls allow it.
6. Checkpoint: call `recon_checkpoint(status)` first. For each pending phase call `begin`; if already running, inspect artifacts and resume. After verifying outputs, call `complete` with summary, counts, and workspace-relative paths. Use `block`, `fail`, or `unavailable` with a reason when needed. Only `vulnerability_testing` may be deferred: call `begin`, then `defer`. Fix checkpoint rejection reasons; never claim success without saved output.

## Workflow

0. **Resume/scope/workspace:** reuse or initialize the canonical root workspace. Recover checkpoint and files first. Configure/check scope only when new, changed, or unresolved. Complete scope/workspace setup only after their checks pass. If authorization is unclear, don't send active requests.

1. **`asset_discovery`:** enumerate seed subdomains using useful passive sources (CT, `subfinder`, Amass, assetfinder, APIs). Merge normalized unique hosts into root `subdomains.txt`; preserve partial results and source failures.

2. **`live_hosts_ports`:** process each candidate with suitable DNS/HTTP/TLS checks; record results/errors. Save root `live-hosts.txt`; save `ports.txt` only if port checks ran and were permitted. Unprocessed does not mean dead or in scope.

3. **`url_collection`:** collect from every eligible in-scope host using useful crawlers, sitemaps, app/HTML links, captures, history, API descriptions, other collectors, and user input. Split inputs if a tool accepts one URL only. Merge into root `urls.txt`; remove exact duplicates but preserve meaningful method/path/query variants. Gather JS, source maps, API/auth routes, and sensitive-file candidates as soon as found. Track source/input as success, empty, failed, or pending.

4. **`directory_fuzzing`:** use suitable non-destructive path discovery only when permitted. Merge paths into `urls.txt`; save `directories/path-discovery.md` with target, tool/version, wordlist+hash, method/rate/settings, counts, exclusions, errors, and useful response fingerprints. If blocked/inapplicable, mark unavailable with a reason.

5. **`parameter_discovery`:** derive parameters from URLs, forms, captures, API descriptions, and JS first. Use tools only to close a real gap and when permitted. Merge into root `parameters.txt`; include endpoint/method/location/source and observed-vs-inferred status.

6. **`parameter_fuzzing`:** only low-impact, permitted discovery checks; use a baseline/control and change one variable at a time, no exploit payloads. Save root `parameter-tests.md` with settings/results or a truthful blocked/not-applicable reason.

7. **`javascript_analysis` (priority):** gather candidates from all sources—`urls.txt`, crawlers/history, HTML/imports, captures, other collectors, user links, extensionless JS responses, source maps. Submit every eligible in-scope URL with provenance to `ingest_javascript_urls` or an equivalent scope-enforced collector; track each as fetched, dedup/cache hit, out of scope, failed, or pending. Never bypass scope. Analyze each unique URL/content version and source maps as inert text; never execute them. Use `correlate_javascript` or an equivalent verified analyzer. Extract endpoint/method/path, parameters, source locations, auth/header/cookie/role/feature clues, and redacted secret fingerprints—never raw secret-like values. Track pending/out-of-scope/missing/partial/malformed/truncated maps honestly. Save non-empty root `javascript-analysis.md` and `endpoints.txt`, including explicit zero-result or incomplete status; supporting evidence goes under `javascript/` and `endpoints/`.

8. **`endpoint_inventory`:** merge URL, JS/map, capture, API, and saved evidence into root `endpoints.txt`. One identity per **origin + method + normalized path template**; query parameters alone don't create duplicate rows. Merge parameter/source/auth evidence. Record an explicit zero-result status if none were found.

9. **`vulnerability_testing`:** if not explicitly requested, begin then defer with reason and continue. If requested, require completed endpoint inventory plus passed scope/policy/runtime controls. Use baseline/control and one controlled change at a time. Save root `findings.md` and redacted evidence under `testing/`, `findings/`, or `evidence/`. Validate before claiming a finding; if safe testing cannot proceed, record the actual blocker.

10. **`reporting`:** create/update root `reports/recon-final.md` from saved artifacts/checkpoints. Verify artifact paths and counts. Distinguish discovered, in-scope, fetched, analyzed, inferred, tested, confirmed, failed, and unresolved. Include source failures, limitations, and the exact resume point. Never claim exhaustive coverage without evidence.

Use the matrix/checkpoint rules rather than guessing. The sequence controls progress, not tool choice. Don't skip work silently or repeat completed work just to increase activity.

## Final response

Keep it brief: status, workspace path, verified counts, report/artifact paths, useful evidence, and real blockers only.
