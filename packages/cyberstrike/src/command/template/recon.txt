# CyberStrike Recon

Run the requested reconnaissance workflow in one pass. The shared Target Workflow is the authority for scope, workspace, skills, tool choice, errors, and reporting. This file defines the recon sequence only.

## Sequence

1. **Resume setup.** Reuse the existing workspace and checkpoint. Initialize only if missing. Configure/validate new or changed scope once; complete the scope and workspace checkpoints before advancing the ledger. Inspect saved artifacts and resume unfinished work instead of repeating completed work.

2. **Discover assets.** Find useful available tools and independent sources dynamically. Keep collecting while new sources add useful candidates. A related hostname or shared IP alone does not prove ownership or permission. Merge normalized hostnames into root `subdomains.txt`, retaining source and failure information.

3. **Verify live hosts.** Resolve and check only eligible in-scope hosts. Check additional services only when permitted. Save verified hosts to root `live-hosts.txt`; keep failures separate from zero results and unprocessed hosts.

4. **Collect URLs and paths.** Use available crawlers, site maps, HTML links, browser captures, API descriptions, and other useful sources. Merge absolute HTTP(S) URLs into root `urls.txt`; preserve meaningful variations. Run non-destructive path discovery when it adds value and save its results/settings under the canonical recon artifacts.

5. **Find parameters.** Prefer URLs, forms, captures, API descriptions, and JavaScript; use other methods to close a real gap. Save normalized records to root `parameters.txt` and parameter-check results or a clear reason to root `parameter-tests.md`. Keep observed data separate from inferred data.

6. **Analyze all eligible JavaScript.**
   - Gather unique URLs from live HTML, scripts/modules, inline scripts, crawlers, captures, URL inventories, extensionless JavaScript responses, imports, and source maps. Resolve relative URLs against the observed page URL.
   - Send the full deduplicated set to `ingest_javascript_urls` or the best registered equivalent. Download first, then analyze the files that were actually saved. Include dynamically discovered imports and maps; do not use arbitrary count limits.
   - After interruption, resume pending items for the same target. Keep a clear status for every URL; failed downloads are not analyzed files. Do not execute downloaded scripts.
   - Extract routes, methods, parameters, headers, authentication hints, application features, API operations, browser storage/messaging, imports, and source locations. Correlate these leads with observed requests and other evidence. Redact secret values and treat static indicators as leads, not findings.
   - Save the combined analysis to root `javascript-analysis.md` and merge discovered endpoints into root `endpoints.txt`. Do not stop after a small sample.

7. **Merge endpoints.** Combine URL, JavaScript, API-description, and captured-request evidence into `endpoints.txt`. Normalize by origin, method, and path template. Preserve meaningful differences and distinguish inferred routes from observed requests.

8. **Close out.** If the user did not request targeted testing, do not start it; mark it deferred and continue. If testing was requested, follow the saved scope and program rules, then save verified results in root `findings.md` with redacted supporting evidence. Generate and verify one final report at `reports/recon-final.md`.

## Simple working rules

- Use the exact workspace path returned by `target_workspace`. Initially, only `scope/`, `assets/`, and `runs/` exist; create a destination directory before writing files into it. Prefer target artifact tools for canonical files.
- Use the existing checkpoint as the single phase ledger. Mark work complete only after verifying the real output and required files. Use an explicit zero-results or incomplete reason where appropriate.
- On failure, inspect the error, exit status, partial output, and process state. Fix the cause or choose another method; do not repeat the same failed command or launch duplicate long-running work.
- Keep independent work moving, merge and deduplicate results, and calculate report counts from the saved artifacts. Distinguish discovered, eligible, live, downloaded, analyzed, inferred, tested, and confirmed results.
- The final report must state what worked, the saved counts and paths, source failures, remaining gaps, and the exact resume point when work remains.
