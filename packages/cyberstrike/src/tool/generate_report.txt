Compile all session data into a structured Markdown security assessment report. Returns a complete report with vulnerability findings, coverage statistics, methodology progress, chain opportunities, attack surface mapping, assessment timeline, agent performance, and validation status.

The report contains three `<!-- AI: ... -->` placeholder sections that you MUST fill in:

1. `<!-- AI: executive_summary -->` — Write 2-3 paragraphs summarizing:
   - Overall security posture and risk level (Critical/High/Medium/Low)
   - Total findings by severity and critical risks identified
   - Key attack chains and their business impact
   - Assessment completeness (coverage %, methodology %)

2. `<!-- AI: risk_assessment -->` — Write a risk assessment:
   - Risk matrix based on likelihood × impact for each critical/high finding
   - Business context and exploitation complexity
   - Systemic patterns (e.g., "all auth endpoints lack rate limiting")

3. `<!-- AI: remediation_priorities -->` — Write a numbered priority list:
   - Most critical items first
   - Each item: finding reference [SEVERITY-NNN], specific action required, expected effort (quick win / medium / significant)
   - Separate quick wins from long-term improvements

After receiving the report output:
1. Read the compiled Markdown carefully
2. Write all three AI sections based on the actual findings data
3. Replace each `<!-- AI: ... -->` placeholder with your written content
4. Resolve the canonical workspace with `cyberstrike target tree <parent-url>` and save the final report using the `write` tool:
   - Use the exact `metadata.recommendedReportPath` returned by `generate_report`; it is the stable `reports/security-final.md` in the selected child or parent workspace.
   - Complete the three AI sections and replace the same file at that path. Do not create a new timestamped copy on each generation.
   - Use `.cyberstrike/reports/security-final.md` only when no canonical target workspace exists.
   Do not put a child-only report in the parent folder or mix several assets into one child report. The generated data is session-level unless the included content has been explicitly scoped to a single asset.

Do NOT skip the AI sections. They are the most valuable part of the report — the deterministic data is compiled automatically, but the executive analysis requires your reasoning.

The `include_sections` parameter allows generating partial reports. Default includes all sections.

### Target-specific report behavior
- For one program or target tree, pass `target_url` as the saved parent URL. Descendant assets are included by default.
- For one asset only, pass its `target_url` with `include_children: false`.
- Target-limited reports filter findings by their persisted target workspace IDs, filter intelligence/coverage/requests to the selected workspace host/path boundaries, and explicitly count findings excluded because they belong to another workspace or were never attributed. Do not re-add excluded findings manually.
- The report metadata includes `recommendedReportPath`. Fill the three AI placeholders, then update that exact stable path so the parent report stays in the parent `reports/` directory and child reports stay under the child workspace. Repeated generation for the same workspace replaces this current report rather than creating another timestamped file.
- Methodology and agent-performance values remain session-wide; the target report labels them accordingly. The target-limited validation section intentionally does not claim a session-wide gate result is asset-specific.

### Automatic target report persistence
When a target workspace is selected, `generate_report` writes the generated report draft to the stable `reports/security-final.md` path and returns it as `metadata.recommendedReportPath`. Complete the three AI placeholders and overwrite that same file with the finished report; do not create one new report file per call. If `target_url` is omitted and exactly one observed root program matches the session, the root and descendants are selected automatically. If multiple root programs are observed, choose `target_url` explicitly; the tool refuses to mix programs.
