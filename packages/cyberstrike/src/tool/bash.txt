Executes a bash command in a persistent shell session. Commands run in ${directory} by default; use `workdir` instead of `cd`.

## Recon execution
- For target work, initialize or reuse the canonical target workspace and use its exact returned path.
- Keep target outputs inside that workspace. Write directly to canonical inventories, merge and deduplicate existing results, and retain raw output only when it adds useful provenance or debugging evidence.
- Do not create per-tool, per-host, per-retry files or unnecessary temporary copies. Reuse stable workspace-local scratch paths only when a tool requires a file, then normalize the result and remove the scratch file when it has no lasting value.
- Do not repeatedly verify the same workspace, re-check unchanged scope at the model level, or run status/checkpoint calls after every command. Request-level scope enforcement remains mandatory.
- Choose suitable available tools for the actual evidence gap. Phase labels and tool catalogs are not tool allowlists. Ordinary recon commands must not be blocked by stale phase state.
- Do not impose arbitrary total time limits, source caps, result caps, or attempt caps on useful recon. Preserve partial results after real failures and continue with a suitable alternative.
- Prefer running independent useful commands in parallel when that improves coverage. Avoid needless duplicate work and unbounded duplicate requests.
- Use `timeout` for a command only when needed for actual process management or a tool-specific requirement; do not add arbitrary short deadlines that cut off useful enumeration.
- Verify meaningful outputs, exit status, counts, and saved paths before claiming success.

## Command usage
- Quote paths containing spaces.
- Run CLI and terminal operations here; use dedicated file tools for source-file reading/editing when available.
- For short independent commands, parallel tool calls are fine. Chain dependent commands in order.
- Do not claim a process or phase completed while it is still running or its output has not been verified.

## Authorization and safety
- The persisted scope manifest and request-level runtime checks are authoritative. Never bypass a scope refusal or broaden scope to make a tool work.
- Recon remains non-destructive by default. Vulnerability testing, exploit attempts, credential attacks, and state-changing actions require an explicit user request and the appropriate testing checkpoint.
- Preserve evidence accurately, redact secret values in general notes/reports, and distinguish candidates from verified findings.

## Output
Be concise. Describe the command's purpose in a short phrase when useful, capture its output, and report only verified results and genuine blockers.
