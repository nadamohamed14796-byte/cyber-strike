# Target Workflow

This file is the single source of truth for target work. Keep other prompts short and specific; do not copy these rules into them.

## 1. Start once
- Reuse the existing target workspace, saved scope, todo list, and checkpoint. If none exists, initialize one workspace for the program/root and use the exact path returned by the tool.
- A workspace stores evidence; it does not grant permission. When scope is new, changed, or unresolved, configure and validate it once. Reuse an unchanged saved decision.
- Accept an explicitly confirmed exact asset or complete supplied scope list. Do not infer sibling domains or widen scope. Exclusions always win. Every actual network request and redirect must still pass runtime scope enforcement.

## 2. Find and load skills
- All valid catalog skills should be searchable and loadable by name. Do not preload the entire catalog.
- When a skill is relevant, search by the observed technology, behavior, vulnerability, tag, or CWE; load the exact canonical result and confirm that full content was returned. Search results and outlines are not loaded instructions.
- Read companion files only through the loaded skill's returned paths. Follow a chain partner only when its stated prerequisite and the current evidence apply.

## 3. Choose tools by the evidence gap
- Use registered tools, connected APIs, helpers, and verified CLIs that fit the task. The phase list and tool catalog are guidance, not an allowlist. Discover alternatives when a useful capability is missing; install a tool only when the task needs it and a trusted installation path is available.
- Do useful independent collection in parallel when supported. Keep one owner for each shared inventory/checkpoint; merge other results afterward.
- Do not ask the user to continue between routine steps. Ask only for a genuinely missing decision. Recon is non-destructive by default; targeted vulnerability testing requires explicit user request and authorization.

## 4. Follow the evidence workflow
For a normal web recon run, proceed through:
1. Reuse workspace and validate scope/checkpoints.
2. Discover in-scope assets from useful independent sources.
3. Verify live hosts and permitted services.
4. Collect URLs, paths, parameters, forms, API descriptions, and browser-captured requests.
5. Download and analyze all eligible JavaScript/source-map assets, then correlate their routes with observed requests.
6. Merge one endpoint inventory.
7. Run vulnerability tests only when explicitly requested; otherwise mark that phase deferred.
8. Generate and verify one final report.

Use the appropriate skill at the phase or when new evidence appears. Do not repeat a completed scan without a changed input, new evidence, or a clear reason. Do not apply arbitrary total-asset or JavaScript limits.

## 5. Save results once
- Keep one canonical workspace and one authoritative checkpoint. Use target tools for scope, artifacts, notes, and run summaries; do not invent alternate directories or duplicate status ledgers.
- Only assume scope/, assets/, and runs/ exist after workspace initialization. Before shell redirection to recon/, javascript/, findings/, reports/, or another nested path, create its parent directory. Prefer the artifact tool for canonical inventories.
- Merge/deduplicate into canonical files while preserving source provenance and useful partial results. Keep raw logs only when they add evidence or help diagnose a failure.
- Report counts from the actual saved artifact. Keep discovered, in-scope, live, downloaded, analyzed, inferred, tested, and confirmed counts distinct. An empty result must say zero-results; incomplete work must state why.

## 6. Recover instead of looping
- On failure, inspect the error, exit status, partial output, and process state. Fix the cause or switch to a materially different method; never repeat an unchanged failing command.
- If a checkpoint or save is rejected, repair that exact issue and retry. A planned action, non-empty file, or checkpoint call is not proof of success.
- Resume unfinished work from the existing cursor/checkpoint. Do not restart everything because one source failed, and do not claim completion while required artifacts or work remain unresolved.

## 7. Close clearly
Save and verify the final report in the canonical workspace. Summarize the result, actual counts, report path, useful evidence, failed sources, limitations, and the exact resume point when work remains. State what was observed versus inferred or confirmed. Do not invent findings or remove the workspace at closeout.
