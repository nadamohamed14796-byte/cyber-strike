## Verification notes

- Worker environment isolation uses an explicit allowlist in `hackbrowser-subprocess/worker-environment.ts`; Bedrock/Vertex credential variables are forwarded only for the matching provider. The optional local server password is passed via the one-time IPC options payload because `CrawlOptions` requires it for local ingest authentication; it is removed from the worker-options object after writing the start message and is not inherited via env. Focused tests were added, but have not been run in this review environment.
- `TargetMemory.addNote` sanitizes titles, content, source labels/URLs, and tags at the persistence boundary. Metadata strings are now single-line normalized to prevent Markdown injection. Regression tests cover multi-word secrets and embedded newline/tab sequences; the regex spot-check is not a substitute for the package suite.
- `TargetMemory.writeWorkspaceFile` atomically writes generated JavaScript correlation artifacts after validating each target directory component and rejecting symlink/non-regular output files. Regression coverage verifies a symlink cannot overwrite an outside file; this has not been executed under Bun.
- AuthVault now validates each stored record’s identity/origin/purpose/timestamps, one-line bounded account fields, targetID format/purpose separation, and AES-GCM payload structure, and rejects duplicate IDs before exposing records. Target ID checks were corrected to test actual CR/LF/NUL characters. Writes enforce a private data-directory mode, clean up temporary files, and serialize in-process save/remove read-modify-write operations. Multi-process locking and runtime verification remain open.
- Target workspace creation walks each directory component with `lstat`, rejects symbolic links/non-directories, and verifies the resolved path stays under the active project root. Target metadata files are checked for symlinks before use. `notes.md` additions/metadata changes now use the safe atomic workspace writer instead of direct `appendFile`/`writeFile`; notes are read only when their target ID belongs to the active project, and generated artifacts verify persisted target identity before writing. Regression tests cover workspace/file symlinks, project-boundary reads/writes, and unknown-session target context rejection; explicit foreign-project research-context coverage and runtime execution remain open.
- The Chromium path/installer subprocess now uses `execFileSync` argument arrays, a minimal environment, and ordinary TLS verification; this removes shell-string execution and the previous `NODE_TLS_REJECT_UNAUTHORIZED=0` override. Installer behavior requires runtime validation.
- Gmail OAuth token refresh, Gmail API requests, and complete OTP search now have explicit request deadlines; the Hackbrowser IPC handler has a 15-second abort and returns a manual-fallback response instead of holding the sole stdout reader indefinitely. The OTP sender boundary keeps the exact normalized site hostname and accepts only that host or a true subdomain; a `www` target does not automatically trust its parent domain. Gmail action arguments are validated before consent prompts. These changes are statically reviewed but not tested against live Gmail or a mocked stalled network.
- Auth-manager now validates target ID/origin against the active project’s workspace table before any target-purpose action, and permission scopes use the normalized origin rather than a path/query-bearing URL. Explicit action-by-action tests are still needed.
- Saved-password consent is requested before consuming `CYBERSTRIKE_AUTH_PASSWORD`, and the local reference is cleared in a `finally` path. Validation tool output now uses actual line breaks for target-note status.
