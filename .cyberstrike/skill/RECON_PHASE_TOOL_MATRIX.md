# Recon Phase Matrix: State, Artifacts, and Completion

This matrix defines phase objectives, dependencies, canonical outputs, and completion checks—not tool assignments or runtime state. The workflow lives in `packages/cyberstrike/src/command/template/recon.txt`; `recon_checkpoint` owns resumable progress and runtime transitions; `.cyberstrike/skill/TOOLING_CATALOG.md` is the shared, non-exhaustive tool/helper reference; specialist skills own technique-specific procedures.

At every checkpoint, choose any suitable available tool based on the evidence gap, capability, saved results, runtime, and policy. This matrix is not a tool allowlist, and stale phase state must not block useful ordinary recon. Preserve request-level scope enforcement and the explicit opt-in for vulnerability testing. Bare filenames below are canonical root inventories unless an output area is named; subdirectories hold necessary raw/structured evidence, not duplicate normalized inventories. If this guidance conflicts with runtime validation, follow the runtime contract and reconcile the documentation.

## Phase matrix

| Canonical phase | Required saved artifact(s) | Completion condition | Boundary / dependency |
|---|---|---|---|
| `scope_validation` | Saved scope manifest and `scope.txt` | Preserve the authoritative policy/source, include/exclude rules, unsupported entries, decision, and ambiguity. Validate the canonical starting asset once during initial setup and reuse the saved decision while target/policy are unchanged. | Must precede active work. A workspace is not authorization. |
| `workspace_setup` | Verified canonical workspace and its initialized run state | Confirm required directories and manifest/checkpoint exist; verify absolute workspace path. | Initialize once and resume the same workspace for the same program/root. Never guess an output directory. |
| `asset_discovery` | `subdomains.txt` | Save normalized, deduplicated hostnames immediately. Preserve partial results and continue when any source fails. | Use suitable available sources; do not wait for every source to finish before moving on. |
| `live_hosts_ports` | `live-hosts.txt`, `ports.txt` when port checks are permitted | Preserve DNS/HTTP/TLS/service evidence, response status, timestamps, errors, and raw-versus-normalized distinction; verify counts and paths. | DNS or HTTP liveness does not prove scope or a vulnerability. Run port checks only when program policy allows. |
| `url_collection` | `urls.txt` | Process every eligible in-scope host using suitable available crawling/API/history sources; retain per-input/source result states, deduplicate exact identities, and preserve meaningful parameter/method variants. | Never weaken request-level scope checks or send a multi-host list to a tool that accepts one URL. Reuse verified results when inputs and tool versions are unchanged. |
| `directory_fuzzing` | Canonical path inventory/evidence in the permitted workspace | Record the selected source/wordlist and hash, target, method, request/rate settings, outcome, exclusions, and relevant response fingerprints. | Only if policy permits; keep rate/impact bounded. This phase is not a blanket requirement to run every directory tool. |
| `parameter_discovery` | `parameters.txt` | Record parameter name/location, endpoint template, method, source, auth/content-type context, confidence, and observed-versus-inferred state. | Prefer local URL/form/JS inventories first; use active discovery only after the phase and policy gates permit it. |
| `parameter_fuzzing` | `parameter-tests.md` | Preserve baseline, single-variable request change, settings, response comparison, negative controls, result, and stop condition. | No uncontrolled brute force or repeated state-changing requests. |
| `javascript_analysis` | `javascript-analysis.md`, `endpoints.txt`; detailed evidence under `javascript/`, `endpoints/`, or `testing/` only when useful | Analyze each distinct bundle version once using URL plus content hash; correlate request/capture IDs, routes, methods, parameters, source locations, and auth/header/cookie clues. Parse captured version-3 source maps and analyze available `sourcesContent` entries without saving source text; record every external `sourceMappingURL` with analyzed/pending/out-of-scope/incomplete status. Verify canonical summaries and artifact paths. | Do not execute untrusted JavaScript or source maps. Retain secret fingerprints and source locations, not raw candidate values. A map with missing or partial embedded sources, malformed JSON, or truncation is incomplete, not complete. Findings require separate validation. |
| `endpoint_inventory` | `endpoints.txt` | Normalize to one record per origin + method + path template; merge parameter/source/auth evidence without discarding meaningful variants; verify counts and paths. | Mandatory before targeted vulnerability testing. Avoid duplicate endpoint rows caused solely by multiple parameters. |
| `vulnerability_testing` | `findings.md` and linked evidence when testing is explicitly requested | Each candidate has a hypothesis, preconditions, baseline/control, minimally impactful test, request/response evidence, validation status, limitations, and stop condition. | Do not begin before endpoint inventory. For a recon-only run, defer this phase with an explicit reason and continue to reporting. |
| `reporting` | `reports/recon-final.md` | Verify report and evidence paths, redaction, reproduction detail, impact/limitations, truthful phase/source counts, and precise blockers/resume point. | The report must match the persisted ledgers; never claim completion when work remains pending. |

## Source and phase status

Source failures and stale phase state must not block ordinary recon. Verify the canonical inventory and continue from available evidence.

When a capability is missing, select a suitable available alternative if one closes the same evidence gap. Otherwise record the precise unavailable/blocked reason and continue only with independent work permitted by the phase gate. Never invent results, weaken scope enforcement, or report a missing source as successful.
