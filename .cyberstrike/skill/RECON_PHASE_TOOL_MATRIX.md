# Recon Phase Matrix: State, Artifacts, and Completion

This matrix defines phase-specific objectives, canonical artifacts, evidence requirements, and optional tool examples only. The Target Workflow Contract at `packages/cyberstrike/src/agent/prompt/methodology/target-workflow.txt` is the single authority for orchestration, scope, retries, partial handoffs, evidence retention, and closeout. The recon command at `packages/cyberstrike/src/command/template/recon.txt` provides the concise phase sequence; `.cyberstrike/skill/TOOLING_CATALOG.md` is the shared, non-exhaustive tool/helper reference; specialist skills own technique-specific procedures. This matrix is not a tool allowlist.

The intended order is asset discovery → live hosts → URL/candidate classification → JavaScript/source-map analysis → parameter discovery → permitted path discovery → final endpoint inventory → optional active tests → report. Keep the canonical artifacts below, and use subdirectories only for useful raw/structured evidence rather than duplicate normalized inventories. Preserve request-level scope checks and explicit opt-in for active testing.

## Phase matrix

| Canonical phase | Required saved artifact(s) | Completion condition | Boundary / dependency |
|---|---|---|---|
| `scope_validation` | Saved scope manifest and `scope.txt` | Preserve the authoritative policy/source, include/exclude rules, unsupported entries, decision, and ambiguity. Validate the canonical starting asset once during initial setup and reuse the saved decision while target/policy are unchanged. | Must precede active work. A workspace is not authorization. |
| `workspace_setup` | Verified canonical workspace and its initialized run state | Confirm required directories and manifest/checkpoint exist; verify absolute workspace path. | Initialize once and resume the same workspace for the same program/root. Never guess an output directory. |
| `asset_discovery` | `subdomains.txt` | Save normalized, deduplicated hostnames immediately. Preserve partial results and continue when any source fails. | Use suitable available sources; do not wait for every source to finish before moving on. |
| `live_hosts_ports` | `live-hosts.txt`, `ports.txt` when port checks are permitted | Preserve DNS/HTTP/TLS/service evidence, response status, timestamps, errors, and raw-versus-normalized distinction; verify counts and paths. | DNS or HTTP liveness does not prove scope or a vulnerability. Run port checks only when program policy allows. |
| `url_collection` | `urls.txt` | Process every eligible in-scope host using suitable available crawling/API/history sources; retain per-input/source result states, deduplicate exact identities, and preserve meaningful parameter/method variants. | Never weaken request-level scope checks or send a multi-host list to a tool that accepts one URL. Reuse verified results when inputs and tool versions are unchanged. |
| `javascript_analysis` | `javascript-analysis.md`, `endpoints.txt`; detailed evidence under `javascript/`, `endpoints/`, or `testing/` only when useful | Analyze each distinct bundle version once using URL plus content hash; correlate request/capture IDs, routes, methods, parameters, source locations, auth/header/cookie clues, browser-boundary signals, and available source/lockfile evidence. Parse captured version-3 source maps and analyze available `sourcesContent` entries without saving source text; record every external `sourceMappingURL` with analyzed/pending/out-of-scope/incomplete status. Persist scope-checked captured JS/source-map response bodies under `javascript/captured/` and index them in `javascript/captured-index.json`; treat raw assets as sensitive local evidence. Verify canonical summaries and artifact paths, and do not complete JavaScript analysis without verified non-empty source evidence or an evidence-backed unavailable status. | Do not execute untrusted JavaScript or source maps. Retain secret fingerprints and source locations, not raw candidate values. A map with missing or partial embedded sources, malformed JSON, or truncation is incomplete, not complete. Findings require separate validation. |
| `parameter_discovery` | `parameters.txt` | Record parameter name/location, endpoint template, method, source, auth/content-type context, confidence, and observed-versus-inferred state. | Prefer local URL/form/JS inventories first; use active discovery only after the phase and policy gates permit it. |
| `directory_fuzzing` | Canonical path inventory/evidence in the permitted workspace | Record the selected source/wordlist and hash, target, method, request/rate settings, outcome, exclusions, and relevant response fingerprints. | Only if policy permits; keep rate/impact bounded. This phase is not a blanket requirement to run every directory tool. |
| `endpoint_inventory` | `endpoints.txt` | Normalize to one record per origin + method + path template; merge parameter/source/auth evidence and any OpenAPI/Swagger/Postman contract metadata without discarding meaningful variants; compare declared operations with observed requests and keep contract-only vs live-confirmed status explicit. Verify counts and paths. | Mandatory before targeted vulnerability testing. Avoid duplicate endpoint rows caused solely by multiple parameters. A missing operation or a contract-only route is not by itself a vulnerability. |
| `parameter_fuzzing` | `parameter-tests.md` | Preserve baseline, single-variable request change, settings, response comparison, negative controls, result, and stop condition. | Active testing is opt-in: defer this phase unless the user explicitly requests parameter tests; use a baseline/control, one variable at a time, and avoid destructive/state-changing payloads. |
| `vulnerability_testing` | `findings.md` and linked evidence when testing is explicitly requested | Each candidate has a hypothesis, preconditions, baseline/control, minimally impactful test, request/response evidence, validation status, limitations, and stop condition. | Do not begin before endpoint inventory. For a recon-only run, defer this phase with an explicit reason and continue to reporting. |
| `reporting` | `reports/recon-final.md` | Verify report and evidence paths, redaction, reproduction detail, impact/limitations, truthful phase/source counts, and precise blockers/resume point. | The report must match the persisted ledgers; never claim completion when work remains pending. |

## Phase checklist and cleanup gate

`recon_checkpoint` synchronizes the compact numbered `[recon:phase_id]` todo list from the saved manifest. Scope validation and workspace setup are hard prerequisites; active testing additionally requires explicit user opt-in and a completed endpoint inventory. Ordinary phase transitions must not stall because an earlier passive phase has a stale or partial status.

The central workflow contract defines how to use the `handoff` action, retry without loops, verify canonical outputs, and preserve scratch/evidence. A partial phase remains labelled partial in the manifest and can be reopened when new evidence or a materially better method appears.

## Source and phase status

Source failures and stale phase state must not block ordinary recon. Verify the canonical inventory and continue from available evidence.

Use the Target Workflow Contract for tool-selection, recovery, and status rules. The entries in this matrix describe evidence needs, not mandatory binaries. A missing source does not invalidate results from other sources; a tool failure or partial handoff must retain its reason and resume point. Never invent results or weaken scope enforcement.
